# ORBSession — Opening Range Breakout (US Session) Strategy Design

**Fecha:** 2026-05-20
**Autor:** Liz (con Walter)
**Status:** Draft v1 — pendiente review de Walter, después handoff a Sofia (quant) + writing-plans
**Rol:** estrategia mecánica KISS para **diversificar** `SMC_Forge` LIVE. No es reemplazo.

---

## 1. Intent

Construir una estrategia freqtrade `ORBSession` que:

1. Opere **Opening Range Breakout** sobre la sesión US (13:00-21:00 UTC) en BTC y ETH perps.
2. Tenga **lógica determinística sin parámetros optimizables** en el baseline → cero superficie de curve-fit.
3. Sea **auditable visualmente** (un humano puede verificar cada trade con lápiz y papel sobre el gráfico).
4. Diversifique `SMC_Forge`: edge basado en expansión de volatilidad post-apertura, no en estructura de mercado.

**No-goals:**

- No reemplazar SMC_Forge.
- No optimizar performance del baseline vía hyperopt en v1 (eso viene en v2 como ablation).
- No multi-sesión (Asia/EU). Solo US. Multi-sesión se evalúa solo si v1 produce edge medible.

## 3. Mecánica de trading (reglas exactas)

### 3.1 Universo y timeframe

| Item | Valor |
|---|---|
| Exchange | Binance USDM |
| Pares | `BTC/USDT:USDT`, `ETH/USDT:USDT` (perps) |
| Apalancamiento efectivo | 1× (lev=1, sin amplificación) |
| Timeframe operativo | 15m |
| Direccionalidad | Long y Short (ambos lados del rango) |

### 3.2 Sesión y rango

| Item | Valor |
|---|---|
| Inicio sesión | 13:00 UTC |
| Fin sesión | 21:00 UTC |
| Ventana de rango | 13:00 - 14:00 UTC (4 velas de 15m) |
| Ventana de entries válidos | 14:00 - 20:45 UTC (último entry posible a 20:45) |
| Cierre forzado | 21:00 UTC |

**Cálculo del rango (al cierre de la vela 13:45):**

```
range_high = max(high[13:00], high[13:15], high[13:30], high[13:45])
range_low  = min(low[13:00],  low[13:15],  low[13:30],  low[13:45])
range_pct  = (range_high - range_low) / close[13:45]
```

### 3.3 Entry

**Long:** vela 15m cierra estrictamente por encima de `range_high`. Entry = close de esa vela.

**Short:** vela 15m cierra estrictamente por debajo de `range_low`. Entry = close de esa vela.

**Filtros activos:**

- `range_pct > MAX_RANGE_PCT` → **skip-la-sesión-ese-par** (default `MAX_RANGE_PCT = 0.015`).
- Si ya hubo un trade (winning o losing) esa sesión en ese par y `ALLOW_REENTRY=False` (default) → **no se vuelve a operar ese par esa sesión**.
- Fines de semana → **no se skipean** por default (`SKIP_WEEKENDS=False`).

### 3.4 Stop loss

| Lado | Stop |
|---|---|
| Long | `range_low` |
| Short | `range_high` |

Risk por trade = ancho completo del rango. `stop_pct = range_pct` para la sesión (calculado al cerrar 13:45).

**Implementación en freqtrade**: el stop se aplica vía `custom_stoploss()` (el `stoploss` de clase queda en `-0.99` como placeholder no-binding). `custom_stoploss` lee `range_low`/`range_high` del dataframe enriquecido y devuelve el porcentaje exacto vs entry.

### 3.5 Exit

Solo dos formas de cerrar:

1. **Stop-out**: precio toca `stop_price`.
2. **Cierre forzado**: vela de 20:45 (última del día válida de exit, cierra a 21:00 UTC).

**No hay:**
- Trailing stop.
- Target R-multiple.
- Break-even shift.
- Time-stop intermedio.

### 3.6 Position sizing

`stake_amount` fijo en config (freqtrade nativo). Default: USD notional fijo por trade. Trivialmente cambiable a `unlimited` o `% equity` editando un campo del `.json`.

## 4. Configuración (parámetros)

Todos como **class attributes** de `ORBSession` con defaults razonables. Configurables vía freqtrade config o override en `__init__`.

```python
class ORBSession(IStrategy):
    # === Sesión (UTC) ===
    SESSION_START_HOUR = 13     # apertura US
    SESSION_END_HOUR = 21       # cierre US
    RANGE_END_HOUR = 14         # fin de cálculo del rango

    # === Filtros ===
    MAX_RANGE_PCT = 0.015       # skip-sesión si rango > 1.5% del precio
    ALLOW_REENTRY = False       # NO re-entry tras stop-out
    SKIP_WEEKENDS = False       # SÍ operar sábado/domingo

    # === Mecánica freqtrade ===
    timeframe = '15m'
    can_short = True
    use_exit_signal = True
    process_only_new_candles = True
    startup_candle_count = 96   # 24h de 15m para warmup

    # === ROI / stop hardcoded en estrategia, no en config ===
    minimal_roi = {"0": 100}    # ROI gigante = nunca cierra por ROI
    stoploss = -0.99            # placeholder; stop real es custom_stoploss
```

**Hyperopt:** baseline v1 corre **sin hyperopt**. Cero `IntParameter` / `DecimalParameter`. Esto es decisión consciente — ver §6 Validation.

## 5. Flujo de datos (cómo opera en runtime)

```
Vela 15m cierra
   │
   ├─ ¿hora UTC < 14:00?
   │     └─ Sí: si 13:00 ≤ hora < 14:00, acumular high/low del rango. No emitir señal.
   │
   ├─ ¿hora UTC == 14:00?
   │     └─ Cerrar el rango. Calcular range_high, range_low, range_pct.
   │        Si range_pct > MAX_RANGE_PCT → marcar sesión como "skipped" en state.
   │
   ├─ ¿14:00 ≤ hora < 20:45 y sesión NO skipped?
   │     ├─ ¿close > range_high y no hay trade abierto y no hubo trade esa sesión?
   │     │     └─ Emit ENTRY LONG con stop = range_low.
   │     └─ ¿close < range_low y no hay trade abierto y no hubo trade esa sesión?
   │           └─ Emit ENTRY SHORT con stop = range_high.
   │
   └─ ¿hora UTC >= 20:45 y hay trade abierto?
         └─ Emit EXIT (cierre forzado).
```

**State per par per sesión:**
- `range_high`, `range_low`, `range_pct`, `skipped: bool`, `traded_this_session: bool`.
- Resetea cada día UTC a las 13:00.
- Persistido en DataFrame de freqtrade (columnas: `orb_range_high`, `orb_range_low`, `orb_skipped`).

## 6. Plan de validación (gates secuenciales)

### Gate 1: Backtest histórico (2-3 años)

- **Datos:** Binance USDM klines 15m, BTC + ETH, 2023-01-01 → 2026-04-30 (~3.3 años).
- **Fees:** maker 0.02%, taker 0.05% (Binance USDM defaults). Slippage: 0.05% adicional.
- **Métricas obligatorias a reportar:**
  - Total trades, win rate, avg win/loss en R.
  - Profit factor, max drawdown, Sharpe.
  - PnL distribution por día de semana, por mes.
  - **Correlación de equity curve diaria vs `SMC_Forge` LIVE** — si Pearson > 0.6 con SMC, la diversificación falló.

**Gate 1 pass criteria:**
- Profit factor > 1.2.
- Max DD < 25%.
- Correlation vs SMC_Forge < 0.4.
- Trades > 200 (significancia estadística mínima).

### Gate 2: Forensics (handoff a skill `bt-forensics`)

Pasa Gate 1 → corre `bt-forensics`:
- Walk-forward analysis (12 ventanas de 90d in-sample, 30d out-of-sample).
- Monte Carlo 10k iteraciones de orden de trades aleatorizado.
- Régimen splits: bull / bear / chop por trimestre.
- Concentración de profit: top 10% de trades aportan ≤ 50% del PnL.

**Gate 2 pass criteria:**
- OOS profit factor > 1.0 en ≥ 70% de las ventanas walk-forward.
- Monte Carlo: P5 de equity final > 0.
- Sin concentración patológica (top 10% trades < 60% PnL total).

### Gate 3: Paper trading (30 días)

Pasa Gate 2 → dry-run de freqtrade conectado a feed real Binance, 30 días.
- Métrica de aceptación: **PnL paper consistente con backtest expectation ±30%** (intervalo basado en var Gate 2).
- Verificación operativa: **0 errores no recuperables**, restart automático funciona, alertas a Discord configuradas.

### Gate 4: Live con capital mínimo

Pasa Gate 3 → live con `stake_amount` inicial = **el menor de $200 o 0.5% del equity de la cuenta-test**.
- Primeros 30 días: live monitoring diario por Walter.
- **Promote a sizing definido por Walter** si: 30 trades completados, profit factor > 1.0, sin discrepancias paper-vs-live > 15%. El sizing target post-promote lo decide Walter en función de equity y de cómo se siente con la mecánica observada.

## 7. Risk management y kill criteria

### Risk por trade (estructural)

- Stop = ancho del rango. En BTC típicamente 0.3-1.5% del precio → con `stake_amount = $S` por trade, loss esperada por stop = `S × range_pct` (rango 0.003-0.015 × S).
- Sin re-entry → máximo 1 trade × 2 pares × 1 sesión = **2 trades concurrentes máximo**.
- Sin apalancamiento → exposure ≤ stake_amount × n_trades. Con stake=$200 y 2 pares: max exposure $400.

### Kill criteria (apagar bot)

- **Drawdown intra-mes > 8%** desde peak → pausa automática, review obligatorio.
- **5 stops consecutivos** (cualquier par, cualquier sesión) → pausa, review manual.
- **Discrepancia paper-vs-live > 25%** en cualquier ventana 7d → pausa, audit operativo.
- **Gate 4 sin promote a 60 días** → kill definitivo, post-mortem, no resurrección.

## 8. Testing

### Unit tests (`test_orb_session.py`)

Mocks de `dataframe` freqtrade. Cubrir:

1. **Cálculo del rango**: dado 4 velas con highs/lows conocidos, `range_high/low` correctos.
2. **Skip por rango ancho**: rango > 1.5% → `skipped=True`, no entries emitidas en ventana 14:00-20:45.
3. **Entry long**: vela 14:15 cierra > range_high → ENTRY long emitida con stop=range_low.
4. **Entry short**: vela 14:15 cierra < range_low → ENTRY short emitida con stop=range_high.
5. **No re-entry**: tras stop-out o exit, ninguna ENTRY más esa sesión, aunque haya breakout opuesto.
6. **Exit forzado 21:00**: trade abierto en 20:45 → EXIT emitida.
7. **Reset diario**: al cruzar 13:00 UTC del día siguiente, state se reinicia.

### Integration test

Backtest de 1 mes (abril 2026) con datos reales descargados vía freqtrade. Verificar:
- Número de sesiones procesadas = días × 2 pares (≈60 sesiones).
- Trades emitidos consistentes con expectativa manual (revisar 5 sesiones random a ojo).

## 9. Diversificación verificable vs SMC_Forge

Métrica oficial: **Pearson correlation de retornos diarios de equity curve ORBSession vs SMC_Forge**, computada sobre la misma ventana de backtest.

Targets:
- `|corr| < 0.4` → diversificación válida, sigue.
- `0.4 ≤ |corr| < 0.6` → diversificación débil, evaluar si vale la complejidad operativa de mantener 2 bots.
- `|corr| ≥ 0.6` → **fracaso de la tesis de diversificación**. Kill.

Análisis adicional en `analysis.ipynb`:
- Solapamiento temporal de trades (¿están abiertos a la vez con frecuencia?).
- Decomposition: días donde ORB gana y SMC pierde, y viceversa.

## 10. Decisiones explícitas (anti-revisitar)

| Decisión | Valor | Razón |
|---|---|---|
| Hyperopt en v1 | NO | Cero parámetros → cero curve-fit. Memoria `feedback_hyperopt_freqtrade`. |
| Sesiones múltiples (Asia/EU) | NO en v1 | KISS. Evaluar solo si v1 muestra edge. |
| Trailing stop / target R | NO | Memoria `bt-forensics` — trailing es responsable del 30% de whipsaw mata-sistemas. |
| ATR-based stop | NO | Stop = nivel estructural (opuesto del rango), no nivel calculado. Auditable visualmente. |
| Risk-based sizing | NO (notional fijo) | Walter eligió notional. Freqtrade lo cambia con un campo del .json. |
| Más pares (top 5+) | NO en v1 | BTC+ETH = liquidez confiable en US session. Altcoins en v2 si v1 funciona. |
